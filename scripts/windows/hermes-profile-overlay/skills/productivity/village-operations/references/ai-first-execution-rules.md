# AI-first execution rules

Use these rules for broad operational commands, partial registration, and manual
quote delivery.

## Investigation and clarification

- Start safe read-only investigation before asking for confirmation.
- Ask only when live evidence cannot resolve ambiguity that materially changes
  money, equipment, recipient, schedule, or an irreversible effect. Broad scope
  alone is not ambiguity.

## Registration authority and partial completion

- A current staff instruction containing `등록` authorizes the exact live customer
  request. Do not require an older staff-acceptance message as second authority;
  establish the customer's request and exact cart from current evidence.
- For `가능하면 등록`, register the verified available subset when exclusions do
  not change the remaining booking's meaning. Record each exclusion and reason.
  Block the whole request only when an excluded item is essential or safe partial
  registration is unavailable.

## Quote interpretation and delivery

- A rental surcharge expressed as a unit price follows the established
  per-requested-unit, per-billable-day convention unless the source says it is a
  flat total or supplies contradictory units. Do not ask a routine pricing question
  when the live conversation and catalog convention already resolve it.
- For an approved official manual quote, default to finance GAS
  `sendEstimateManual` through Popbill Alimtalk. Reading Kakao may establish the
  current cart, but a stopped Kakao browser does not block Popbill delivery.
- Use direct Kakao file attachment only when staff requests that channel or the
  provider delivery failed while the same exact artifact remains authorized.
- After staff has seen the exact current preview, a bare `보내` authorizes that
  unchanged artifact. Require another approval only if evidence or content changed.
