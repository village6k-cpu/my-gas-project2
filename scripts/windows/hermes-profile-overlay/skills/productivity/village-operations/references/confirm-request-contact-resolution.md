# 확인요청 연락처 누락 처리

## 목적
확인요청을 실제 스케줄/거래로 등록하기 전에 고객 식별과 연락처를 안전하게 확정한다.

## 순서
1. 확인요청을 먼저 생성하되 연락처가 없으면 `등록` 단계에서 멈춘다. 연락처 공란을 임의 값으로 채우거나 전화번호 없이 스케줄을 만들지 않는다.
2. 고객 DB에서 **정확 이름 + 연락처**로 먼저 찾는다. 이름에 직함·공백·별칭이 있을 수 있으므로 정규화/부분 일치 후보도 조사할 수 있다.
3. 부분 일치 후보는 **정확히 1명일 때만** 자동 반영한다. 둘 이상이면 후보와 연락처를 사용자/담당자에게 확인받는다.
4. DB에 후보가 없으면 해당 고객의 Kakao 대화에서 연락처를 찾거나, 고객에게 예약 등록용 연락처를 요청한다. 고객 대화가 자동화에서 열리지 않거나 식별되지 않으면 그 사실을 짧게 보고하고 연락처 확보를 요청한다.
5. 연락처를 입력한 뒤에는 가용확인을 다시 실행하고, 충돌이 없을 때만 등록한다.
6. 마지막으로 확인요청 행의 `연락처`, `결과`, `등록상태`, `거래ID`를 재조회하여 중복·부분등록·등록대기가 없는지 검증한다.

## 금지사항
- 이름만 같다는 이유로 다른 고객의 전화번호를 입력하지 않는다.
- 연락처 누락 상태에서 반출/반납 스케줄 또는 거래를 선등록하지 않는다.
- 가용확인 결과가 있는 경우에도 연락처 입력 후 재확인을 생략하지 않는다.

## 보고 형식
짧게: `✅ 등록 완료` 또는 `⏸ 연락처 미확보 — 확인요청만 생성, 스케줄 미등록`으로 상태와 다음 한 가지 필요한 조치를 명시한다.
