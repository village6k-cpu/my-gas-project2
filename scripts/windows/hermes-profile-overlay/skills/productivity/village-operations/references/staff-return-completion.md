# 직원 판단에 따른 반납완료

2026-11-04 대표 확정 정책: 직원의 완료 버튼 또는 정확한 거래에 대한 “반납완료 처리해줘”는 명시적인 완료 지시다. 본체·구성품을 하나씩 입력하거나 추가로 정상 반납 여부를 재확인받는 절차를 강제하지 않는다.

- 앱은 기존 `toggleReturn`의 `force: true`를 내구 outbox에 저장한다. 준비 초안·미입력 구성품 수량·교체 미정리만으로 반납을 거절하지 않는다.
- 서버의 `lock_packing_completion`과 `guard_packing_manifest`도 이 정책을 따른다. 직원 인증, 동시 완료 잠금, 완료 revision CAS는 유지한다.
- 정상·파손·분실 수량이나 준비 확정 여부를 임의로 채우지 않는다. 개별 기록 생략은 물리적 미반납으로 단정하지 않는다. 실제 파손·분실 기록은 보존한다.
- Slack 처리도 직원 지시를 그대로 실행한다. 상세 수량이 비었다는 이유로 추가 질문하거나 수락된 완료를 되돌리지 않는다.
- GAS ACK만으로 성공을 말하지 않는다. 앱의 인증된 `/api/gas`를 사용하거나 GAS ACK의 정확한 `returnDone`·`returnDoneAt`·`completionRevision`을 `apply_trade_completion`에 반영한 뒤 정본을 다시 조회한다. 이미 완료된 거래는 재실행하지 않는다.
- 실제 네트워크·권한·동시 수정 실패는 별도로 처리하고, 미입력 수량을 그 실패 원인으로 바꾸어 설명하지 않는다.

관련 마이그레이션: `20261104003832_staff_return_completion.sql`. 운영 반영 시 `village-heybilli-dashboard/SKILL.md`의 과거 필수 수량 확인/반납 차단 지침도 함께 교체한다.
