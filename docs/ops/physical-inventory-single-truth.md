# 장비 ID 기준 단일 실물 재고

장비마스터 B열 `장비ID`와 같은 행의 재고 수량이 실물 기준이다. 세트마스터는 판매 상품·구성·단가 기준이며, 판매명 하나가 실물 재고 하나라는 뜻이 아니다. 기존 시트의 구조와 열 순서를 바꾸지 않는다.

## 사고 경로와 수정

2026-10-16 확인: `난룩스 이보크 1200B`는 구성품이 있는 판매 세트, `NANLUX Evoke 1200B`는 다른 판매명으로 동시에 존재했다. 실물은 `LGT-011` 한 대인데 한글명과 ID의 검증된 연결이 없었다. 기존 가용성 경로 일부는 문자열 완전일치만 사용했고, 구성품을 전개하는 다른 경로는 미연결 세트 헤더를 생략했다. 직원 승인 등록은 수요를 우선 보존하고 후속 재고 검토를 큐에 넣는 정책이라 등록 성공 자체가 가용성 보장이 아니었다.

`inventoryIdentity.js`는 기존 `inventory_identity_aliases` 및 같은 ID·정확명이 일치하는 원장의 별칭을 장비마스터에 연결한다. 새 장비·수량을 만들거나 유사도만으로 장비를 바꾸지 않는다. 잘못된 중복 연결은 모호성 오류이며 임의로 한 장비를 선택하지 않는다.

- 가용성 조회, 선택적 스케줄 읽기, 세트 헤더, 등록 일정 변경은 같은 연결을 사용한다.
- 헤더에 해당하는 본체가 명시적인 구성품 행에 있으면 헤더를 중복 점유하지 않는다. 구성품의 제외·반납·외부조달 상태를 헤더로 되살리지 않는다.
- 캐시된 점유 지도는 장비 ID·정확명·검증된 별칭의 버전에 결속한다.
- 등록 영수증에는 `inventory_review.identity_bindings`가 실물 ID를 남긴다. 연결됨은 재고 충분 또는 외부조달 확정이라는 의미가 아니다.
- 미해결 세트 헤더가 미해결 구성품 전개로 사라지지 않고 AI 신원 검토에 남는다.
- 진짜 신규·외부 조달 수요를 기록하는 정책과 직원 확답의 수요 보존은 유지한다. 가용 보장과 공급 충돌 보고는 구분한다.

## 운영 검증

내부 인증의 `run/getInventoryIdentityCatalog`는 읽기 전용으로 ID·정확명·별칭만 반환한다. `getInventoryRiskReport(true)`로 정본 스케줄 전체를 다시 읽어 동일 ID의 겹침을 확인한다. 기존 상업명·수량·가격·일정·체크아웃 상태는 이 연결 때문에 변경하지 않는다.

이번 사고의 원본 일정은 `260915-006-01`과 `261014-020-17`이며 2026-10-18 22:00부터 10-19 03:00까지 보유 1/점유 2다. 검증된 별칭 연결은 `record_inventory_identity_review`의 대상 ID·정확명·updated_at 비교로 한 번 반영했다. 부족한 실물 한 대를 조달·대체하거나 고객과 취소를 합의하는 것은 별도 업무이며 연결 수정만으로 해결됐다고 보고하지 않는다.

운영 별칭 연결의 review ID는 `0bdf230a-f665-4574-b933-079e8fcb20b7`이며 운영 GAS의 읽기 전용 위험 보고에서 위 두 예약의 5시간 중복·1대 부족을 재확인했다. 신규 행동 테스트 21개 및 별도 리뷰는 통과했다. 호스트 메모리 복구 후 최신 전체 테스트는 1060개 중 1051 통과/9 생략/0 실패였다. 통합 시 main에서 다시 검증하고 운영 배포 후 새 읽기 전용 API와 실제 위험 보고를 대조한다.
