# 과거 할인유형 복원 — 금액 보존 모드

`restoreTradeDiscountMetadata`는 서버 내부 인증 + POST 전용이다. 계약서에 실제로 적용된 할인유형을 계약마스터 K열에 복원하며, 일반 할인변경 API와 달리 계약서를 재생성하지 않는다. 기존 계약서의 모든 값·수식, 거래내역의 금액·입금·링크, 고객DB 기본값을 보존한다. 시트 구조나 열 순서를 바꾸지 않는다.

1. `tid`, `discountType`, `previousDiscountType`(공란 포함), 새 `mutationId`, `dryRun:true`로 검사한다.
2. 검사 응답의 금액·문서 링크·복원 유형을 원래 합의와 대조한다. 현재 고객DB를 과거 자격의 근거로 소급하지 않는다.
3. 같은 입력에 `expectedSnapshotDigest`를 넣고 `dryRun`을 제거하여 1회 전송한다.
4. 응답과 계약마스터·`getTradeDiscountState`를 새로 읽어 K열과 Supabase 투영을 확인한다. 기존 원장 금액·문서 링크가 보존됐는지도 대조한다.

전송 전에 mutationId와 digest를 운영 기록에 남긴다. 응답이 유실되거나 `readbackRequired:true`이면 쓰기를 재시도하지 않고 정본을 읽는다. 미완료 영수증은 자동 재실행을 차단한다. 완료 영수증이 있는 같은 요청은 정확히 일치하는 readback에만 중복 성공을 반환한다.

고객명·연락처는 계약서의 예약자(상호)·연락처 필드에서 검증한다. 거래ID 중복, 다른 거래의 계약서, 금액 불일치, 진행 중인 재생성, 변경된 기준선은 차단한다. 구형 문서나 복합 할인은 해석되지 않는다는 이유로 새 금액을 계산하지 않는다. 보류하고 원문·최종 견적·정산액을 별도로 대조한다.

구형 양식에서 식별정보 칸이 비어 있으면, 필요한 라벨이 모두 존재하고 파일명이 정확히 `계약서_<거래ID>_<예약자명>`이며 거래내역의 고객명·연락처·반출일과 계약마스터가 일치할 때만 빈 칸을 원장 근거로 검증한다. 한 파일이 여러 거래에 연결되거나, 채워진 고객정보·기간이 모순되면 복원하지 않는다. 문서의 빈 칸 자체를 채우지는 않는다. Sheets의 실제 Date 값은 문자열로 바꾸기 전에 각 원본 스프레드시트에 저장된 시간대로 비교한다. 시트 자체의 시간대는 변경하지 않는다.

구형 날짜 문자열의 네 자리/두 자리 연도와 `2026년 4월 8일` 표기를 검증한다. 연도 없는 `4월8일13시`와 숫자 `260425`는 위의 정확한 거래별 파일명으로 결속된 문서에서만 허용한다. 생략된 연도는 거래ID의 연도로 결속하며, 반납 월일이 반출보다 앞서면 다음 해 한 번까지만 비교한다. 존재하지 않는 달력 날짜와 의미가 모호한 `24시`는 원문 확인 전 차단한다. 고객명 접미사나 회사명 별칭을 자동으로 동일인으로 간주하지 않는다.

원래 할인금액 자체가 누락된 건, 회차·서비스 장비·수동 쿠폰 정정, 환불·추가 청구·증빙 변경·고객 발송은 이 경로의 대상이 아니다. 특히 과거 학생20%, 학생+단골·제휴 조합과 수동 정산을 현재 정책으로 덮어쓰지 않는다.

직접·메뉴·큐 재생성은 `deleteAndRegenerateContract`의 짧은 ScriptLock 선점 + 거래별 `contractDirectRegen_v1_` 표식을 공유한다. 외부 Drive/원장 작업 동안 전역 잠금을 유지하지 않으며 복원 경로는 이 표식이 있으면 쓰지 않는다.

조회용 Supabase 동기화는 최근 30일 timeline 윈도우 밖 거래에서도 거래내역의 실제 금액과 기존 계약서 링크를 읽는다. 계약마스터·거래내역의 유일한 거래ID, 고객명·연락처·반출일, 유일한 문서 연결, 양의 정수 금액과 재생성 미진행을 확인한 경우에만 두 조회 필드를 보강한다. 현재 할인율로 금액을 재계산하지 않으며 입금·결제·증빙·반출 상태는 변경하지 않는다. 원장 조회 자체가 실패하면 빌드를 실패시켜 dirty 표식을 유지한다. 개별 식별 충돌·빈 금액·공유 문서는 기존 조회 필드를 그대로 보존하고 별도 대조한다.
