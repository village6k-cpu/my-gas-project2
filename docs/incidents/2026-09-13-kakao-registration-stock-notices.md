# 카카오 확정 예약 누락과 재고 알림 중복 — 2026-09-13

## 확인된 경로

해당 예약의 직원 확정은 원래 자동 작업으로 만들어지지 않았다. 앞선 직원 업무의 CDP 스크립트가 수집용 목록 탭을 대화방으로 이동시켰고, 그 시점부터 수집 heartbeat/event가 멈췄다. 프로세스와 포트만 살아 있었다. 워치독은 설치 영수증의 파일 크기 불일치로 복구 전에 종료했다. 이 수집·설치 문제와 접힌 고객 메모 연락처 전달 문제는 앞선 복구에서 수정했다.

등록 전 재고 검사는 유효한 확인요청이 있어야 실행된다. 따라서 수집 실패로 확인요청 자체가 생성되지 않으면 등록도 재고 경고도 발생하지 않았다. 기존 Windows 워치독 실패는 로그와 작업 종료 코드에만 남았으며, 이 실패를 소유자에게 전달하는 독립 경로가 없었다.

Slack 실제 이력은 두 통이 아니라 네 통이다. 공개 문서는 예약과 메시지 식별자를 익명화하고, 원본 증거는 로컬 감사 기록에 보존한다.

| 경과 시간 | 요청 | 관찰 |
|---|---|---|
| 최초 | 요청 A | 최초 복구 입력 중 검사 |
| 28초 후 | 요청 A | 구성품 선택 변경 후 검사, 같은 표시 내용 |
| 약 18분 후 | 요청 B | 기존 요청 교체 후 재발송 |
| 약 40분 후 | 요청 C | 연락처 보완을 포함한 요청 교체 후 재발송 |

네 메시지는 각각 다른 `client_msg_id`와 알림 metadata ID를 가졌다. 첫 두 통은 최초 입력과 소프트박스→젬볼 선택을 별도 API로 처리한 한 native 작업 안에서 생성됐다. 실제 영수증은 `insertAndCheckRequest` 56,031ms와 `updateRequestItem` 26,081ms를 기록한다. 판정 키는 전체 위험 목록으로 바뀌는데 메시지는 앞의 불확실 항목 세 개만 표시했다. 위험이 해소되는 변화도 새 알림으로 취급하고, 새 위험이 뒤에 생겨도 메시지 앞부분은 같아 보이는 문제를 재현했다.

뒤의 두 통은 복구 중 RQ를 교체하면서 이전 발송 이력을 이어받지 않은 별도 결함이다. 이 복구로 생긴 중복도 이번 작업의 책임 범위에 포함한다. 당시 표시된 세 항목은 재고 연결 불확실성이고, 확정된 수량 부족을 의미하지 않는다.

## 변경

- 검증된 알림에 위험 목록을 함께 보존한다. 같은 위험 또는 감소한 위험은 재발송하지 않는다. 새로 생기거나 악화된 위험만 후속 알림에 표시한다. 해소 후 재발은 다시 알린다.
- 정확한 기존 RQ 교체가 완료된 지점에서 이전 RQ를 연결한다. 이름·날짜만으로 다른 예약의 알림을 합치지 않는다. 이전 발송 결과가 불명확하면 원래 메시지 ID를 조회해 조정하고, 새 RQ에서 무작정 다시 보내지 않는다.
- 정상적으로 진행 중인 워커 큐와 배포 전 빈 큐 요구를 분리한다. 일상 워치독의 수집 복구를 정상 업무가 막지 않는다. 배포 전 검사와 재시작 후 검증의 기존 빈 큐 요구는 유지한다.
- 기존 Windows 워치독에서 검증 또는 복구가 실패하면, GAS·예약 요청·AI 워커에 의존하지 않는 소유자 장애 알림을 실행한다. 같은 장애는 영수증으로 중복을 막고 직접 정상 검증 후에만 닫는다. 기존 재고 알림 채널 설정을 사용한다.
- 알림 상태 조회에 정책 버전과 지정한 RQ의 발송 영수증·교체 연결을 추가했다. 쓰기나 재발송 없이 배포 결과를 확인할 수 있다.

가격, 모델 설정, AI의 예약 판단 기준, 스케줄 열 구조를 변경하지 않는다. 기존 07시 재고 요약과 등록 전 경고 일정도 바꾸지 않는다.

## 검증

- 중복·새 위험 표시·RQ 교체·이전 POST 불확실·부족 감소/재발·교체 완료 시점의 여섯 회귀를 수정 전 실패로 확인했다.
- 관련 회귀 101개 통과 후, 기존 영수증 마이그레이션과 실제 PowerShell 워치독의 설치 검증 중단 경로도 추가 검증했다.
- 알림/relay/이전 영수증 회귀 59개 통과, 실제 워치독과 PowerShell 단일 인수 전달을 포함한 독립 장애 알림 검사 7개 통과.
- 실제 Slack 채널의 멤버십과 이력 조회 권한을 읽기 전용으로 확인했다. 시험 메시지는 발송하지 않았다.
- 운영 반영 후에는 GAS 정책 버전, 지정 RQ 영수증, 직접 CDP 수집 상태, 워커 consumer와 기존 예약의 원장을 별도로 확인한다. 과정과 readback은 로컬 감사 폴더에 보존한다.
