# 견적서·거래명세서 자동발송 검증 — 2026-11-10

## 수정 범위

- 응답의 operationId가 요청과 일치해야 문서 발송/준비 영수증으로 인정한다. 다른 작업의 성공 응답을 현재 요청의 성공으로 바꾸지 않는다.
- 거래명세서 완료는 정확한 거래ID의 할 일에만 적용한다. 다른 거래, 여러 거래가 합쳐진 작업, 별도 계약서 수정은 남긴다. 카탈로그 견적도 다른 등록 거래의 할 일을 닫지 않는다.
- 가격 안내와 문서 발송의 중복 키를 구분한다. 동일한 금액을 먼저 안내했어도 이후 요청한 견적서를 누락하지 않는다.
- 파일 선택·전송 버튼 클릭만으로 첨부 발송을 성공 처리하지 않는다. 같은 방에서 해당 파일의 새 발신 카드가 증가해야 확인한다. 예전 첨부, 고객이 올린 파일, 다른 방, 전송 중/실패는 제외한다.
- 실제 저장된 카카오 파일 카드 형식(파일명 바로 뒤 `유효기간…용량`, 발신 카드 오른쪽 여백 20px)을 대조했다. 발신자 메타데이터가 unknown인 경우에는 해당 파일 카드 형식과 좁은 우측 정렬 조건을 함께 요구한다. 일반 메시지 발신자 분류는 바꾸지 않는다.
- 첨부의 중복 change 이벤트와 이중 클릭을 제거했다. 거래명세서 전송 시작을 원자적 파일 생성으로 기록하고, 응답 유실·프로세스 중단 후에는 무조건 다시 보내지 않는다. 확인된 결과만 재사용하며 불확실한 결과는 미완료로 유지한다.
- 문서 API 실패도 자동응대 감사 로그에 기록한다.
- 기존 운영 전용 다중 견적 보호 규칙을 보존하고 저장소에도 반영했다. 여러 거래의 견적을 하나의 계산으로 완료할 수 없다.

변경 파일: `tools/ai-browser-worker/worker.mjs`, `verified-pricing.mjs`, 관련 회귀 테스트, `scripts/test-document-provider-stress.mjs`.
