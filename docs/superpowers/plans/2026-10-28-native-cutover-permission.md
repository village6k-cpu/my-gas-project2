# Native cutover permission and recovery boundary

The Windows source continues operating. This code does not demonstrate a
completed migration or authorize activation from a prepared snapshot.

`scripts/macos/migration_native_cutover.py` coordinates the final permission
transaction through a platform adapter. The actual operator must first bind
the current five-owner stop receipt, final cold transfer, restored databases,
assembled profiles, GBrain validation, held jobs, installed bytes, unchanged
model configuration and quality/performance evidence. All seven gate documents
and their underlying evidence are hash bound to the same intent and stop.

The phase lock protects source closure, activation permission and voice phase
publication. Each document is fully written and fsynced to a private temporary
file, then atomically published without replacing an existing name. A partial
write never becomes a final authority file.

Before any native bootstrap request, the exact permission can be revoked only
with all sixteen jobs absent, no unmanaged native consumer, every service lock
held, the original HOLD phase unchanged and no bootstrap intent. The owned
closure and permission are archived and the original inactive marker restored.
This handles an interruption between permission publication and the first
service request. It does not restart Windows by itself.

The exact GUI browser identity and job must exist before the irreversible
bootstrap intent is recorded. Chrome, bridge, Root, worker, voice and relay start
once. Both gateway platform connections and the core runtime must be ready
before voice authority becomes Mac. The watcher and scheduled jobs follow.
Calendar jobs retain their calendars and do not replay missed runs at bootstrap.

Once a bootstrap request is recorded, an unknown result is never retried and
blind Windows rollback is forbidden. The Mac may already have accepted work.
Recovery then requires current authoritative observations and preservation of
any new Mac data. The source restart tasks remain fenced after activation.

Validation includes twelve synthetic transaction tests: changed evidence,
partial publication, pre-bootstrap revocation, a missing validation browser,
live owners, one-shot launch failures and voice phase ordering. These tests run
without real services or customer writes. Separate real native read-only checks
verify the adapter's launchd, GUI Chrome, process and port assumptions. Synthetic
agent and voice tests do not certify actual customer completion; ordinary
business receipts and cloud readback remain required after cutover.
