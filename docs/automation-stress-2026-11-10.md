# 자동화 스트레스 검증 — 2026-11-10

## 검증 결과

운영 bridge와 같은 Node v24.18.0에서 실행했다.

| 범위 | 통과 | 실패 | 건너뜀 |
|---|---:|---:|---:|
| 카카오 감지·worker·영속 큐·예약 대사·업무 DB | 1700 | 0 | 0 |
| GAS·예약·결제·대시보드 등 기존 회귀 테스트 | 1333 | 0 | 2 |

Mac에서 실행할 수 없는 Windows 전용 테스트 파일 34개는 제외 목록에 기록했다.
실제 고객 발송과 운영 DB 쓰기를 부하 발생 대상으로 사용하지 않았다.
이 결과는 격리된 회귀/장애 주입 검증이며 모든 실제 대화의 처리 완료를 의미하지 않는다.

재실행: Node 24 이상에서 `node scripts/test-automation-stress.mjs`.
DB 테스트 의존성은 `npm ci --ignore-scripts --prefix tools/work-orchestrator-v2`로 설치한다.
스크립트는 임시 폴더에 TAP 원본과 제외 파일을 포함한 `report.json`을 생성한다.

## 추가한 장애 주입

- 예약 작업 120개에 이벤트 480회, 소비자 16개를 투입했다.
- 작업별 쓰기 권한 요청을 동시에 5번 반복해 실제 operation이 하나만 생성됨을 검증했다.
- 성공/부분 실패를 섞고 4회 재시작해 receipt 보존과 사람 확인 상태를 검증했다.
- 응답 유실 32건을 만든 뒤 재시작·lease 만료를 발생시켜 재등록 없이 확인 대기로 남는지 검증했다.
- 응답 유실 예약과 무관한 답장 성공이 예약의 확인 필요 상태를 해제하지 않는지 검증했다.
- 내부 예약 commit 전체를 실행하는 격리 테스트에서 고객 발송 함수 호출이 0회인지 검증했다.

## 재현 후 수정한 결함

1. 내부 예약 반영의 no-send 옵션 이후 별도 예약 알림 함수를 호출하는 경로를 제거했다.
   수동 등록 및 별도 승인된 발송 경로는 그대로 유지한다.
2. 명시적으로 사람 확인이 필요한 업무가 다른 답장의 발송 성공으로 해결 처리되지 않게 했다.
3. 확인 필요 업무와 후속 작업 저장 실패를 `ai_completed`로 표시하지 않도록 구분했다.

## 운영 확인과 한계

- 이전 수정에서 신고된 예약을 복구했고 해당 기간을 원장과 앱에서 재확인했다.
- 이번 검사 시 별도 timeout 예약은 GAS 확인요청·계약마스터 및 앱 거래에서 조회되지 않았다.
  기존 timeout receipt는 보존하고, 현재 원장 확인 없이 자동 재실행하지 않는다.
- 운영 health의 과거 복구 보류·미통지 실패·수집 대기 기록은 별도 대사 대상이다.
  이 테스트 실행은 해당 기록을 삭제하거나 해결 처리하지 않는다.
- 공개 GAS는 버전 200개 한도로 HEAD와 달랐다. 사용자 승인으로 미사용 594번만 삭제했다.
  삭제 전 코드 19개 파일의 압축 백업과 SHA-256 재검증을 완료했다. 운영 814·522는 보존했다.
- 최종 공개 배포 버전 및 실제 처리 결과는 배포 후 별도 readback으로 확인한다.

## 셀프 리뷰

- 시트 구조·열 순서 변경 없음. 공개 API 인증·권한 변경 없음.
- 등록 lock과 중복 방지 로직 유지. 테스트는 임시 디렉터리와 격리 DB 사용.
- 운영 별도 checkout에 저장소 전체를 덮어쓰지 않고 해당 두 Node 파일의 diff만 반영했다.
- 전체 회귀 검증 및 `git diff --check` 통과. 무결함이나 전체 실대화 커버리지는 주장하지 않는다.
