# Hermes native and browser tools

This migration replaces the root Orca discovery skill with Hermes's existing canonical cua-driver skill, archives Orca-only CLI/orchestration skills, repairs executable resolution, and connects a target-bound Playwright MCP tool to the already-authenticated dedicated Chrome at loopback port 19223. The old built-in browser toolset is disabled because its shared CDP CLI retargeted another page during an actual test. Existing Village/skills tools, model, and approval settings are preserved.

The browser adapter uses Playwright's existing CDP driver. Every open returns an opaque handle to an exact Page object; every later action requires it. There is no implicit current tab, positional selection, or fallback after a closed/missing handle. Task-owned popups receive separate handles. Actions return fresh accessible page state; close/shutdown affects owned pages only. Existing customer/watch tabs must retain their IDs and URLs during verification. Native tests use an isolated Cua socket and a disposable document on display 16MR70. The old Cua and Orca installations are not removed; only the isolated Hermes Orca launcher is disabled.

The tested native runtime is the officially signed cua-driver 0.20.0 bundle (Team YCK386LBJ7). Version 0.38.0 rejected the current Hermes input contract and is not selected. For a normal cold start, driver.py launches the exact pinned .app path with standard permissions; it does not use LaunchServices' ambiguous `-a CuaDriver` name lookup. Existing explicit Hermes embedded-session approval settings remain owned by Hermes. Existing native daemons on other sockets are untouched.

Run switch.py with the isolated installation root and an officially signed driver binary inside its tools directory. The default is a dry run. Review the paths before adding --apply. It refuses to apply while a selected gateway reports active agents. Use --service root and --service worker separately to switch idle services without changing a busy peer. Backups include exact original files and installed hashes under control/ui-tools-backups. The service manifest hashes are updated for the changed tool settings; original activation gates remain unchanged. No credentials, customer records, model, prices, queues, or financial settings are changed. Gateways must be gracefully restarted only after active work drains so their new executable environment is loaded. The native wrapper pins the tested driver protocol and reads permissions from its own short socket; it refuses automatic upgrades that could reintroduce the verified 0.38 argument mismatch.

Hermes Desktop uses the separate ~/.hermes profile. desktop.py backs it up and configures the same browser server plus a native-only Cua MCP allowlist, avoiding the Desktop build's older native adapter. It localizes linked computer/browser skills before writing and archives only the profile's Orca skill links, preserving the shared ~/.agents source. Existing gbrain/my-rag servers and provider settings are preserved. The command defaults to dry run and requires --apply for changes. Start a fresh Hermes conversation to load the new tool catalog; existing conversations may retain cached tools.

Acceptance evidence is kept privately under the installation's control/ui-tools-verification directory: two independent MCP clients saved separate form values despite tab switching; foreign and closed handles were refused; all 11 pre-existing tab IDs and URLs were preserved. Native text editing and a checkbox were read back from the exact test window. A separate cold socket initialized MCP, reported existing TCC grants, and listed apps through the pinned bundle. Unit checks cover no-write dry runs, preservation, active-work refusal, manifest drift, sequential service switching, and Desktop configuration.

Roll back by checking installed hashes against the backup receipt, restoring the original files and archived skill directories, removing only receipt-listed new files, and restarting the idle gateways. Never restore queues or resend customer messages as part of this tool migration.
