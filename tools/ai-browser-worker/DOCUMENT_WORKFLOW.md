# 고객 요청 서류 자동 처리

고객이 요청한 견적서와 거래명세서는 대화·현재 원장을 확인한 뒤 기존 공식 서류 API로 처리한다.
고객의 요청은 변경 없는 검증된 서류의 자동 발송 의사다. 같은 건에 대표 승인을 다시 요구하지 않는다.
수기 금액 수정, 미등록 단가, 미승인 할인, 수신 권한 충돌은 구체적인 근거와 함께 검토 대상으로 남긴다.

## 정보 확인과 대화 계속하기

기존 대화, 방 메모, 정확한 원장, 고객 DB에서 먼저 필요한 정보를 찾는다.
남은 고객 정보는 `document_clarification`에 서류 종류, 누락 필드, 현재 방의 고객 메시지 ID를 명시하고 한 번에 묻는다.
이미 확인한 정보를 재질문하지 않는다. 내부 거래 ID나 매장 단가를 고객에게 요구하지 않는다.
질문을 보냈어도 서류 업무는 열린 상태로 유지하며 다음 답변에서 같은 요청을 계속 처리한다.

일반 응답 복구 보류를 해제하지 않고 기존 `verifiedPricingAutoSendEnabled` 범위에서만 서류 확인 질문을 허용한다.
운영 일시정지, 현재 방 확인, 새로운 메시지·직원 응답, 발송 중복 검사는 그대로 적용한다.
복구 건은 활성화 이후 접수된 건의 같은 방·작업·리비전·최신 고객 발화를 호스트가 새로 읽어 검증해야 한다.

## 여러 서류

단일 서류의 기존 `price_quote` / `statement_request` 형식은 유지한다.
여러 날짜 또는 견적서와 거래명세서 동시 요청은 `document_requests`를 사용한다.
각 요청은 서류 종류, 정확한 가격 조회 대상, 고유한 `task_key`를 갖는다. 거래명세서는 예약자명도 필요하다.
각 서류를 별도로 검증하고 모든 수신자·기간·금액을 먼저 검사한 뒤 발송한다.
같은 거래의 견적서와 거래명세서 금액을 합산해 이중 청구액처럼 안내하지 않는다.
고객 안내에는 검증된 합계 또는 모든 일정별 금액을 사용하며 검증되지 않은 금액을 섞지 않는다.

## 발송과 완료

견적서는 공식 API의 동일 작업 ID를 재조회하여 실제 제공자 발송 확인을 받는다.
거래명세서는 정확한 거래의 비공개 PDF를 준비하고 같은 고객방에 파일로 첨부한다.
PDF 준비나 전송 버튼 조작만으로 완료 처리하지 않는다. 새 발신 파일과 안내문 확인이 필요하다.
거래명세서 전송은 개별 서류의 지속 작업 기록을 선점한다. 순서 변경, 일부 선택, 단일/묶음 전환으로 중복 발송할 수 없다.
결과가 불명확한 기록은 자동 재발송하지 않고 확인 대상으로 유지한다.

일부만 발송됐으면 각 성공 영수증을 보존한다. 확인된 서류와 정확히 연결된 업무만 완료한다.
다른 거래의 가격 검토나 예약 업무는 유지한다. 운영 보고에는 요청 수와 발송 확인 수를 구분한다.

## 검증

Node 24에서 다음을 실행한다. 이 테스트는 고객 전송을 모의 처리한다.

```sh
node --test tools/ai-browser-worker/document-workflow.test.mjs tools/ai-browser-worker/verified-pricing.test.mjs tools/ai-browser-worker/verified-document-recovery.test.mjs tools/ai-browser-worker/document-delivery-stress.test.mjs
node scripts/test-automation-stress.mjs
```

운영 파일에 별도 수정이 있으면 기본 커밋과 이번 변경을 세 방향으로 병합하고 기존 운영 기능을 보존한다.
배포 전 진행 중인 지속 작업을 확인하며, 실제 고객 발송으로 테스트하지 않는다.
