# 검증 범위

## 자동 검증

`run-tests.sh <installed-runtime-root>`: 111개 통과. 자동응대·가격·알림 관련 추가 검증 25개를 합쳐 현재 관련 검증은 136개 통과.

- 원문 journal 19개: fsync, 크래시, 손상, 디스크 여유, 정확한 전달 영수증
- intake coordinator 20개: 재기동, 중복, 소스 증거, 불명확 결과 보존, 대기열 공정성, 동시 실행 제한, raw 재수신보다 대기 고객 우선, 보류의 시도 예산 제외
- watcher 9개: ACK, 불완전 대조, 과거 목록 스크롤과 실제 새 메시지 구분
- bridge 통합 5개, 실시간 우선순위 2개, 안전한 재시도 분류 5개
- 적용 전 무효 AI 응답의 무실행 증거와 재시도 제한 4개
- 알림 분리 1개, 재시도 작업 ID와 작업 버전 2개
- 정확한 소유 탭 로딩 3개, 삭제 메시지 안내 문구 3개
- native adapter lifecycle 9개, collector 소유권 6개, 장애·알림 정책 14개
- 반복 설치 3개: 패치가 되돌아가지 않음, native drain 연동, 실패한 패치 거부
- 유휴 배포 조건 3개: 실행 중 업무 보호, 실제 consumer 상태, 오래된 상태 파일 구분
- 실제 로컬 TCP 포트 3개: 실행 중 포트 보호, 정상 종료 후 TIME_WAIT, 설치된 launcher 확인

기존 배포 소스 `server.test.mjs`는 변경 전 148개 통과/6개 실패였고,
이번 변경 후에도 같은 148개 통과/동일 6개 실패였다. 이 전체 테스트 묶음이 전부 통과했다고
보고하지 않는다. 새 회귀 실패는 없으며, 기존 실패는 다음과 같다.

- nested skipped Slack failure의 전달 확인 기대값
- health aggregate 필드의 정확한 fixture
- 등록 변경 executor config fixture
- 등록 대체 Task 7 fixture
- confirmation validator boundary fixture
- health safety contract fixture

이 테스트들의 기존 실패를 해결하기 위해 실제 운영의 영수증 검증이나 저장 fence를 완화하지 않았다.

## 운영에서 별도로 확인한 항목

- 정확한 watcher 프로세스만 종료했을 때 launchd가 새 PID로 재기동
- 운영 전용 collector가 전체 상담 목록으로 복구되며 bridge/consumer 연결 확인
- 14일 대화 목록 스캔이 날짜 경계를 넘어 모든 수신 ACK를 받은 후에만 완료로 기록
- 실제 Gateway 작업의 처리와 finalize가 계속 진행
- 실제 장부 읽기, 기존 거래 품목 수의 readback
- 실제 슬랙 수신과 헤이빌리의 지속적인 장애 사례 표시
- 개별 시스템 실패 DM 반복 발송을 억제하고 실제 가격·서류 확인 요청은 전달
- 2026-11-06: 성공한 가격·서류·Slack 반영 알림은 내부 감사기록에만 보존한다. 가격 불확실·발송 실패·미확인 결과·실제 담당자 업무만 Slack에 남긴다. 기존 대기 성공 알림에도 같은 정책을 적용한다.
- 매니페스트, runtime pin, env hash, 활성화 gates 유지

운영 증거·스크린샷·수신 원문과 고객별 결과는 격리 런타임의 비공개 control/state/queue에 보관한다.
이 저장소에는 고객 연락처, 금융정보, 토큰, 원문 대화를 복사하지 않는다.

## 아직 의미하지 않는 것

대화 목록의 수신 대조 완료는 전체 예약 원장 대조 완료가 아니다. 보관 원문, 안전한 자동 재시도,
처리 결과 미확정 기록을 구분한다. 부분 성공·이미 실행된 작업은 원장과의 일치가 입증되기 전까지
다시 등록하지 않으며, 모든 과거 예약이 정상이라고 결론짓지 않는다.

## 2026-11-06 반복 조회의 중복 대기 수정

같은 작업 ID와 예약 버전인데 조회 시각과 원문 journal 참조만 달라진 작업이 별도 대기로 누적됐다.
원문은 각각 그대로 보관하고, 시각·journal 참조만 다른 동일 작업은 하나의 원본 작업으로 전달 영수증을 연결한다.
실제 품목·수량·본문·대여일·예약 버전 등 업무 값이 다르면 합치지 않는다.
기존 중복도 재시작 후 같은 방식으로 연결하며 작은 묶음마다 이벤트 루프를 양보한다.
이미 디스크에 보관된 재시도는 이후 목록 스캔에서 다시 만들지 않는다. 새로운 고객 요청은 계속 접수한다.
회귀 검증: 중복 원문 보존, 재시작 연결, 업무 값 변경 분리, 대기 작업 관찰, 반복 스캔 억제와 실제 새 요청 통과.

## 2026-11-06 사람의 조치가 필요한 알림만 전달

복구 모드가 전체 `autoSendEnabled`를 끄면서 정상 실시간 문의까지 보류했다. 이제 기존 운영자가 발송을 허용한 설정에서, 실시간 이벤트 검증을 통과하고 복구 기준 시각 이후이며 재수집 이벤트가 아닌 해당 작업만 발송 권한을 복원한다. 공용 설정을 변경하지 않으며 과거 작업 hold, 운영 발송 중지, 가격·최신 대화·화면 확인 검증을 유지한다. 예약 원장과 고객에게 보류된 과거 답변을 일괄 재실행하지 않는다.

성공 응대·서류 발송·직원 보고 반영은 Slack에 새 알림을 만들지 않는다. 부분 서류 실패, 실제 전송 실패, 단가 미확정, 전송 결과 미확인, 미완료 담당자 업무는 계속 알린다. 단순 가격 검증 흔적이나 과거 대조 진행 상황만으로는 담당자 알림을 만들지 않는다. 시스템 장애는 기존 메시지 한 개를 갱신하고 해결 시 제거한다. 기록 원문·내부 감사 이력은 그대로 보존한다.

운영 모듈을 직접 불러오는 가짜 전송 테스트도 별도로 실행해 실제 고객에게 시험 메시지를 보내지 않고 실시간 허용·과거 차단·성공 알림 억제·실패 알림 유지를 확인했다. 원문·Slack 정리 대상과 삭제 영수증은 격리 런타임의 비공개 control 폴더에 보관한다. 전체 과거 예약 대조가 완료되었다는 뜻은 아니다.
