# 계산서 요청 작업대 — 2026-11-02

후속조치의 `계산서 요청` 탭에서 tax_invoice 업무를 분류하고 실제 재무 원장·발행처DB를 대조한다.

- 요청일, 고객, 연결 거래, 대여기간, VAT 포함 금액과 공급가/세액, 발행처·대표자·사업자번호·이메일, 입금 상태, 청구/영수, 발행 관리번호를 표시한다.
- 거래·발행처 보완은 업무 버전 CAS로 저장한다. 새로고침과 발행 완료 이력은 준비한 연결 및 실제 발행 증빙을 우선한다.
- 발행은 서버 dryRun → 업무 버전 재확인 → GAS 스냅샷 CAS → 기존 재무 발행 API → 원장 관리번호 확인 → 업무 완료 순서다.
- 미확정 정보·합산·정정은 사유를 표시하고 단일 거래 발행을 차단한다. 다른 발행처로 바꾸는 편집 중에는 발행할 수 없다.
- 응답 유실·원장 불일치 시 결과 미확인 표식을 보존하고 재발행을 차단한다. 기존 앱 발행 진입점에도 같은 표식을 적용한다.
- 발행 성공 뒤 업무 완료 CAS만 충돌하면 재발행하지 않고 업무 완료만 별도로 처리한다.

검증: GAS 원장/발행 동작, 요청 모델, API 인증·dryRun·결과 유실·완료 CAS, 실제 카드 편집 핸들러 테스트. 초기 독립 검토의 3개 중요 지적을 재현 테스트로 보완했다. 고객에게 실제 계산서를 발행하는 테스트는 실행하지 않는다.

배포: main 통합 스크립트를 사용한다. 사용자의 587 삭제 승인을 받은 뒤 18개 원본 파일과 SHA256을 다시 확인하고 해당 버전만 삭제했다. 저장 버전 199개와 사용 중인 522·809 보존을 확인했다. 백업은 `/private/tmp/gas-version-587-backup.2jVRAi`에 있다. 최근 대표 확인·정리 보관함과 함께 통합하며, 정리 보관된 요청은 보관함에서 복원한 뒤 대기 목록에 다시 표시된다. 운영 배포 및 실제 UI·원본 dryRun 확인 전에는 완료로 보고하지 않는다.
