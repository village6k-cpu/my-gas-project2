# 토스 전화번호 결제 조회 장애 — 2026-11-02

## 원인과 재현

- 운영 `/api/lookup`에서 `장부에서 예약을 찾지 못했습니다` 오류가 반복됐다.
- 전화번호로 검색한 모든 과거 거래를 `refreshPaymentAccounts`에 전달하면서, 정본 장부에 없는 거래 하나가 전체 조회를 502로 중단시켰다.
- 운영 데이터 대조: 취소 제외 검색 인덱스 1,416건 중 정본에 없는 거래 5건, 해당 전화번호 5개. 원본 데이터를 삭제하거나 금액을 추정하지 않았다.
- 동일 고객의 현재 거래 `261031-005`는 거래ID 조회 200 / 228,800원이지만 전화번호 조회는 502였다. 같은 번호의 과거 `260709-006`이 정본에 없었다.

## 수정 범위

- 결제 후보 조회에서만 누락된 거래를 제외한다.
- 이번 정본 스냅샷에서 확인된 거래ID로만 잔액을 읽는다. 이전 잔액 캐시로 누락 거래를 복원하지 않는다.
- 수납 배분·승인 반영 등 쓰기 경로는 기존의 모든 거래 확인 조건을 유지한다.
- 정본 통신 실패, 검토 필요, 결제 완료, 미배분 승인 차단은 유지한다.
- 서버 수정이므로 토스 플러그인 ZIP 변경이나 재설치는 필요 없다.

## 검증

- 누락 이력과 정상 거래가 섞인 회귀 테스트를 수정 전 실패 / 수정 후 통과로 확인했다.
- 누락된 거래만 존재할 때 과거 잔액을 노출하지 않는지, 정본 오류 시 결제를 차단하는지, 쓰기용 갱신은 누락을 계속 거절하는지 검사했다.
- 운영 배포 후 동일 전화번호, 거래ID, 결제 완료 거래를 다시 조회한다.
