# 장비별 동봉 구성품 검수

반출 전 예약 카드에서 `구성품 준비 시작`을 누른 거래에 적용한다. 이미 반출한 거래와 기존 완료 기록은 자동 변환하지 않는다.

1. 장비별로 실제 종류와 수량을 선택한다. `기존 교체`는 해당 줄을 대체하고 `기존 유지하고 추가`는 별도 줄을 남긴다. 제외는 0개로 보존한다.
2. 같은 실물 종류를 명시적으로 선택하면 반납에서 한 번 합산한다. 이름이 비슷한 직접 입력품은 자동 합산하지 않는다. SmallHD 9V, Teradek 2핀, Nucleus-M 7핀은 별도 ID다. 더미·HDMI 규격은 현물에 맞춰 직접 입력하거나 이 거래의 기존 실물 종류를 선택한다.
3. 각 줄의 준비 확인 후 `이 구성으로 반출 준비 확정`을 누른다. SDI or HDMI 같은 미결 선택은 확정할 수 없다. 준비 도중 예약을 수정했으면 `예약 변경 내용 불러오기`로 바뀐 줄을 다시 준비한다.
4. 반납에서는 같은 실물의 총량과 장비별 내역을 보고 받은 수량을 기록한다. 부분 반납은 계속 미반납으로 남는다. 파손·분실 처리에는 사유가 필요하다. 미반납을 남긴 채 강제 완료할 수 없다.

반출을 시작한 뒤에는 기준 목록을 바꾸지 않는다. 추가 반출은 기존 현장 항목 추가 흐름으로 기록한다. 이 기능은 동봉 구성품의 실제 인계 기록이며 예약·단가·재고 마스터를 수정하지 않는다. 자유 메모는 수량으로 자동 해석하지 않는다.

`/packing-demo`는 동일 UI와 검증 로직을 쓰는 체험 페이지다. 예시 데이터만 사용하고 새로고침하면 초기화된다. 실제 저장은 예약 카드에서 한다.

## 저장·배포

- `trades.packing_manifest`: 원본 연결, 실제 구성품, 확정 시각, 실물별 반납 수량, revision. 일반 시트 동기화 writer는 이 필드를 쓰지 않는다.
- `packing_audit`: 직원 ID와 버전별 기록. 서비스 전용 RPC가 trade row lock과 CAS로 저장한다. 직원 브라우저의 직접 JSON 변경은 trigger로 차단한다.
- `packing_dispatched_at`: 완료를 취소해도 실제 반출 이력과 기준선 잠금을 보존한다.
- 완료 요청의 안정적인 mutation token으로 120초 lease를 잡아 GAS 왕복 중 수량 변경을 막는다. 응답 유실은 같은 token으로 재시도한다. GET 완료 요청도 같은 POST 로직으로 합류한다.
- `supabase/migrations/20261028103258_kit_packing.sql` 적용 후 Next.js 배포. GAS 소스 변경 없음.
- 검증: `npm test`, `npm run build`, `test/packing-database.sql` (항상 rollback), 브라우저 교체·추가·반납 검증.
