# 장비 아래 구성품 검수

반출 전 예약 카드에서 `구성품 준비 시작`을 누르면 기존 장비 행 바로 아래에 동봉 구성품을 표시한다. 별도 장비 목록을 만들지 않는다. 이미 반출한 거래와 완료 기록은 자동 변환하지 않는다.

1. `7인치 모니터`는 실제 모델을 등록 목록에서 선택한다. 스몰HD 인디7을 고르면 스몰HD 전원선과 영상선 선택지가 표시된다. 세트에 있던 노가암은 해당 모니터에 배분하며 추가 생성하지 않는다. FX6는 운영자 확인에 따라 롱라인을 LVM, 일반 SDI·노가암을 7인치 모니터에 자동 배분한다. 여러 모니터가 있으면 임의 배분하지 않는다. 세트에 공용 영상선이 이미 있으면 새 선을 추가하지 않고 `기존 영상선 연결`에서 배분한다.
2. `교체·수량`은 등록된 구성품을 선택하는 창이다. 검색어를 이름으로 저장하지 않는다. 기본 목록은 해당 장비와 관련된 구성품이며 전체 등록 목록은 검색으로 찾는다. 미등록품은 확인 후 카탈로그에 등록해야 한다.
3. `기존 교체`는 기존 선을 대체하고 `기존 유지하고 추가`는 별도 줄을 남긴다. 제외는 0개로 보존한다. `사용 장비`는 이 예약의 본체 목록에서 고른다.
4. 같은 등록 ID는 다른 장비 아래에 있어도 합산한다. SmallHD 9V, Teradek 2핀, Nucleus-M 7핀, SmallHD 더미는 서로 다른 품목이다. 이름만 유사하거나 단자가 같다는 이유로 규격을 합치지 않는다.
5. `SDI or HDMI`는 실제 등록 종류를 선택하기 전까지 미확정이다. 총수량은 선택된 품목과 미선택 수량을 따로 표시한다. 모든 종류·수량·제외 여부를 확인해야 반출 준비를 확정할 수 있다.
6. 반납에서는 등록 품목별 합계와 장비별 배분을 함께 확인한다. 부분 반납은 미반납으로 남으며 완료를 막는다. 파손·분실에는 사유가 필요하다.

## 이전 예약 / 이전 준비 목록

- 예전 스케줄에 남은 `SDI 롱라인, SDI 라인, 노가암` 등의 묶음은 명시된 수량 또는 확인된 세트마스터 대응 행으로 분리한다. 애매한 종류·수량은 자동 확인하지 않는다.
- 초기 구현의 준비 중 목록은 `구성품 목록 업데이트`로 변환한다. 원본 예약 행과 메모는 보존한다. 기존 직원이 직접 변경한 내용이 있거나 반출이 시작됐으면 자동 변환을 거절한다.
- 예약 변경 후 `예약 변경 내용 불러오기`를 누른다. 기존 직접 추가·교체 내역을 보존한다. 본체/구성품의 예약 원본이 달라지면 확정 전에 재확인한다.
- 반출 시작 후 기준 목록은 변경하지 않는다. 추가 반출은 기존 현장 항목 추가 흐름으로 기록한다. 가격·예약 장비 변경도 기존 예약/현장 추가 기능을 사용한다.

## 카탈로그와 저장

- `lib/domain/packingCatalog.ts`: 2026-10-28 세트마스터 671행 A/B/C/F에서 읽은 108개 구성표와 명시적 실물 별칭. 가격은 포함하지 않는다. 새 품목 추가나 규격 통합은 이 등록표를 검토하고 배포한다. 자유입력 이름을 자동으로 같은 실물로 추정하지 않는다.
- `trades.packing_manifest`: schemaVersion 2, 원본 연결, 본체 연결(ownerId), 실제 모델(deviceModels), 등록 품목 ID, 확정 시각, 품목별 반납 수량, revision. 이전 확정된 내역은 그대로 읽는다.
- `sources.device=true`: 본체 변경도 확정 시 확인하지만 본체 행을 구성품으로 숨기거나 중복 집계하지 않는다.
- `packing_audit`: 직원 ID와 버전별 기록. 서비스 전용 RPC가 row lock과 CAS로 저장한다. 일반 시트 동기화는 구성품 기록을 덮어쓰지 않는다.
- 기존 `20261028103258_kit_packing.sql` 사용. 이번 수정은 GAS/시트 구조/가격/DB 스키마 변경 없음.
- `/packing-demo`: 실제 HandoverChecklist와 PackingChecklist를 사용한다. 본체는 읽기 전용이고 구성품 조작은 메모리에서만 작동한다.
